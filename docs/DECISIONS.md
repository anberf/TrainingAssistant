# DECISIONS (append-only)

Format: `D## (date) — decision. Why. [task]`

- D01 (2026-11-19) — Phone PWA mirrored to TV is the primary target; direct TV browser is best effort. Why: requirements ask for both mobile-first PWA and TV readability; one landscape fullscreen layout serves both. [setup]
- D02 (2026-11-19) — "Single index.html" = single page app; JS/CSS split into `js/*.js`, `css/app.css` (still no build, no deps). Why: pure modules must be `require()`-able by Node tests. [setup]
- D03 (2026-11-19) — Must be served over HTTP(S); `file://` unsupported. Why: `fetch` of routine JSON and service workers do not work on `file://`. Offline is achieved via the service worker after first load. [setup]
- D04 (2026-11-19) — SUPERSEDED by D11. Reps-based steps do not auto-advance; user presses Enter/→ when done. Timed steps auto-advance. Why: reps have no reliable duration. [setup]
- D05 (2026-11-19) — Routines discovered via `routines/index.json` (static hosting cannot list directories). A test enforces every routine file is registered, so "no code change" holds. [setup]
- D06 (2026-11-19) — Tests: Node built-in `node:test`, no npm deps; JS modules use UMD pattern. Why: offline, zero-install. [setup]
- D07 (2026-11-19) — Back (←) restarts the current step if > 3 s elapsed, else goes to previous step (music-player convention). [setup]
- D08 (2026-11-19) — 5 s get-ready countdown before first step. [setup]
- D09 (2026-11-19) — Automation: implementer = fresh `claude -p --model sonnet`; reviewer = fresh `claude -p --model opus`, read-only tools. Script runs tests itself as the authoritative gate. Implementer commits; script pushes only after APPROVE. [setup]
- D10 (2026-11-19) — Routines authored as blocks with `rounds` + `restBetweenRounds`; `expand()` flattens to timed steps at load. Engine/view only see flat steps. Why: compact, readable JSON for 3-round circuits; engine stays simple. Rest is inserted between rounds only, never after the last. [Q01]
- D11 (2026-11-19) — Supersedes D04. Fully automatic: every step is timed, nothing waits for input. Reps duration = `reps × secPerRep × (perSide ? 2 : 1)`, `secPerRep` default 3 s (per-step override, e.g. Turkish get-up 20 s). Timed `perSide` steps double too. UI shows `×N` / `×N / side` plus countdown. [user change 1]
- D12 (2026-11-19) — Only user controls: Start (once), Pause/Resume, Skip, Back. Primary input = large on-screen tap buttons; keyboard/remote secondary. No exit/menu/fullscreen-toggle keys during a run. Back/Skip keep paused state. [user change 1]
- D13 (2026-11-19) — Pause steps may omit cues (they display the next exercise's cues). Exercises still need exactly 3. [Q01]
- D14 (2026-11-19) — "10/direction" (halo) modeled as `perSide: true`; displayed as "/ side". Routine includes a pause after the last warm-up exercise of each round, as written by the user. [Q01]
- D15 (2026-11-19) — Validator: exercise with missing `cues` errors as `cues: expected 3`; clips reject any URL scheme, `//`, leading `/` or `\`, and `..` segments; `perSide` must be boolean. Expanded flat steps always have `cues` (array, `[]` for Rest) and `perSide` (bool); `reps` only on reps steps; generated Rest carries the block name and the round it follows. [T02]
- D16 (2026-11-19) — Demo routine: 1 block × 2 rounds, 5 s rest between rounds, steps Air squat (10 s), Pause (10 s), Halo (5 reps × 1 s, perSide = 10 s). Registry test also requires index entries to be unique lowercase-kebab `.json` names. [T03]
- D17 (2026-11-19) — Engine API: `create(steps, {readySec=5, onEvent})`; every mutator (`start/tick/togglePause/skip/back`) returns the events it produced (`ready`, `step{index}`, `beep{second}`, `final-beep`, `finished{totalElapsedMs}`). Time is injected (ms); engine never reads a clock. Beeps also play during get-ready (3/2/1 + final at go). Thresholds longer than a segment are skipped; a big tick jump emits every crossed event in order. Total elapsed = active time incl. get-ready, excluding paused time. Skip/back are no-ops in idle/finished; Back in get-ready restarts it; Back at step 0 restarts it; Skip on last step finishes. Restarting a step re-arms its beeps. [T04]
- D19 (2026-11-19) — View-model: countdown = `ss` unpadded (<60) else `m:ss`; `index` is string `n / total`; `blockLabel` omits `round r/n` when rounds = 1. During a pause or get-ready, `target`/`cues`/`clip` come from the NEXT step, `cuesFor: next`, and extra field `focusName` names that exercise (title stays the pause name). Themes: `exercise`, `rest` (pause + get-ready), `done`, `idle`. Last step `nextUp` = "Finish". [T06]
- D20 (2026-11-19) — UI: app.js is a thin IIFE (no exports); static test checks every `$('id')`/`setText('id')` exists in index.html. Picker keeps the "No routine loaded" text, hidden once routines load. Cards are `<button>`s; invalid ones are disabled and show the first error; keyboard selection skips them. Done screen shows `Total time m:ss`. Audio/fullscreen/wake lock left to T08/T09 (engine events not consumed yet). Accent colour via `data-theme` on `#app`. [T07]
- D18 (2026-11-19) — Keys: `mapKey(key, screen)` takes `KeyboardEvent.key` values (also NumpadEnter, Space, Spacebar). Picker: Right/MediaTrackNext/Down = `down`, Left/MediaTrackPrevious/Up = `up`, select keys = `start`. Run: select = `toggle`, Right/Next = `skip`, Left/Previous = `back`, Up/Down and all else null. Done screen (not in SPEC §5): select keys = `start` (activates "Back to routines"), all else null. [T05]
- D22 (2026-11-19) — Screen: screen.js exports global `ScreenCtl.create(doc, nav)` -> `{start, finish, isActive}`; never throws. `start()` (Start tap) requests fullscreen (incl. webkit prefix) and the wake lock; `finish()` (run end or back to picker) releases it. visibilitychange re-acquires only while active, visible, and with no lock held/pending. Fullscreen is not re-entered or exited automatically. [T09]
- D21 (2026-11-19) — Audio: audio.js exports global `Audio2` (avoids clobbering browser `Audio`); `createBeeper(Ctor)` lazily creates one context; all methods swallow errors and return booleans. Extra `onEvent(ev)` maps engine beep/final-beep events to tones; app passes it as the engine's onEvent; `unlock()` runs on the Start tap. Sine tones, gain 0.4, 20 ms release. Beeps are engine events, so none fire while paused. [T08]
- D23 (2026-11-19) — Clip: single `<video id="run-clip">` below cues, hidden until `loadeddata`, re-hidden on `error`; `src` reassigned only when the view-model clip path changes; empty clip clears src. Clip choice is view-model (D19). [T10]
- D24 (2026-11-19) — PWA: `APP_SHELL` excludes `sw.js` and `routines/*` (index, routines, clips are fetched at install from index.json, best effort); `./` also listed. Cache-first with `ignoreSearch`; other same-origin GETs cached at runtime. Icons generated by dependency-free `tools/make-icons.js` (orange kettlebell on #0a0a0a; maskable has smaller glyph). Test loads sw.js in a `vm` sandbox to read `APP_SHELL`. [T11]
- D26 (2026-11-19) — KB 60 routine copied verbatim from the draft (already schema-valid; no content changes) into `routines/`; the draft in `docs/routine-drafts/` is now superseded (could not be deleted in this session; safe to remove, nothing references it). Registry test pins 3531 s / 78 steps / block order. Not added to SW APP_SHELL (D24: routines fetched at install). [T13]
- D27 (2026-11-19) — TV readability: existing tokens already pass 7:1 (test computes from CSS tokens), so landscape sizes are unchanged; added a portrait media query scaling run-screen text by min(vh, vw), letting title (2-line clamp) and cues wrap. Landscape keeps single-line ellipsis. E2E test drives KB 60 with 100 ms fake-clock frames; finish = 3531 s + 5 s get-ready. Not checked visually on real devices. [T14]
- D28 (2026-11-20) — Rest/get-ready: view-model `target` is '' and the next exercise's target is `nextTarget` (rendered only in the "Next:" line); exercise steps unchanged. Sizes: #run-focus 7vh bold, #run-meta 4.5vh, #run-next 5vh; portrait uses min(vh, vw) (focus wraps). Clip max-height lowered 28vh -> 16vh so larger text fits 16:9. Not checked on real devices. [T15]
- D25 (2026-11-19) — Release test reads the first `## vN` heading in CHANGELOG (ignores Unreleased). Existing entries were released as v1 to match `CACHE_VERSION = "v1"`; T12 stays under Unreleased. [T12]
- D29 (2026-11-20) — Picker label is pure `View.cardLabel(weight, totalSec)`; weight omitted when missing/blank/"none" (defensive, so old routines with "none" still look right). Routine-drafts deleted (D26 now historical). Released as v2: CACHE_VERSION "v2", CHANGELOG Unreleased renamed. [T17]
- D30 (2026-11-20) — Rep pace is a user setting on the picker, not a side menu, and not available during a run (D12). A global sec/rep replaces only routine defaults; exercises with their own `secPerRep` (TGU) get their own stepper. Saved per device in localStorage. Why: user wants to adjust the 3 s assumption AND the TGU; a global stepper keeps the TV/remote picker simple. [user change 2, T18]
- D31 (2026-11-20) — Exercise picture is shown beside the rest/get-ready countdown (next exercise), not below the cues. `clip` accepts images as well as video. No media during exercise steps (supersedes T10 placement). Why: pictures are faster to recognize than word cues when preparing for the next exercise. [user change 3, T19]
- D35 (2026-11-20) — Stick figures are generated by `tools/make-clips.js` (pose tables -> SMIL `<animate>` on polyline `points`, head `cx/cy`, kettlebell `animateTransform`); the SVGs are committed and may be hand-edited or replaced via `clip`. The clips test strips the standard `xmlns="http://www.w3.org/2000/svg"` before checking for `http` (needed for a standalone SVG in `<img>`; not a reference). Poses are simplified side views (Russian twist = bell swinging left/right; Leg & hip stretch = knee-to-chest per leg). Not visually checked in a browser. Clips are fetched by the existing SW runtime precache (no APP_SHELL change). [T20]
- D32 (2026-11-20) — Default pictures are original SMIL-animated SVG stick figures drawn in the repo (offline, tiny, no licensing). User can replace any file with own GIF/video by changing `clip`. [user change 3, T20]
- D33 (2026-11-20) — Pace: `Pace.normalize/stepValue/overridable` are pure; limits global 1–6 s (0.5 step), exercise 1–60 s; steppers clamp at limits (no wrap; return to "routine" only via Reset). An exercise override applies to any reps step with that name. Card totals are recomputed from `Routine.totalDuration(routine, pace)` on each render; pace is read once at Start. Panel buttons blur after a tap so Enter/Space still start the routine. [T18]
- D34 (2026-11-20) — View-model `clip` is replaced by `media = {src, kind}|null` (kind from extension: mp4/webm = video, else image); only rest/get-ready have media (the next exercise's clip). Validator allows mp4, webm, svg, gif, webp, png, jpg, jpeg (case-insensitive, query/hash ignored) and errors `clip: unsupported type` otherwise. `#run-img` and `#run-clip` sit in `#run-clock` (height 25vh, max-width 40vw; portrait min(25vh, 30vw)); both hidden until loaded and on error; `src` reassigned only when kind+path changes. [T19]
- D33 (2026-11-20) — Supersedes D32 pictures: the user replaced the stick-figure SVGs with own, more realistic animated GIFs (`clips/<exercise-kebab>.gif`, ~2.6–3.1 MB each, ~39 MB total, all precached by the SW). Clip test now checks GIF header, kebab names, ≤ 5 MB each. [user change]
- D34 (2026-11-20) — The D33 GIFs (photographic, ~39 MB total) are converted to animated WebP: 480×270 (≈ display size at 25vh on 1080p), all 30 frames at 10 fps, quality 70 → ~190–270 KB each, ~3 MB total (13× smaller, less banding than GIF). WebP is already an allowed clip type. Originals stay in git history (970d465). Clip test checks RIFF/WEBP/ANIM header, kebab names, ≤ 512 KB. [user change]
- D35 (2026-11-20) — Picker shows `Version vN` below the routine list, read from `AppInfo.version` (was a stale 0.0.1, now `v3`). A release test pins it to `CACHE_VERSION`, so the label always names the cached build actually running (useful to confirm a phone updated). [user change]
- D36 (2026-11-20) — Turkish get-up clip is an MP4 (`clips/turkish-get-up.mp4`): user video trimmed to seconds 5–55, re-encoded H.264 Main, CRF 26, no audio, faststart, native 144×256 portrait (not upscaled) → 402 KB. - D38 (2026-11-20) — T21: `#run-countdown` is `flex: none; width: 4.4ch; text-align: center` (tabular-nums kept), so its box is identical for 9, 10, 59, 1:00, 2:00 (longest rest is 120 s) and the media beside it never moves. - D39 (2026-11-22) — `routines/*` are served network-first by the SW (cache fallback offline); app shell and clips stay cache-first. Why: the owner publishes routine changes by uploading files to GitHub; with cache-first, devices that already opened the app would not see them until a release. [user change 4, T22]
- D40 (2026-11-22) — Sharing model: the app is static (no server, no accounts), so "only the owner edits" is enforced by GitHub push rights, not by the app. Shared routines = repo files; pace stays per device (§4a), so others can change their own pace freely. Owner mode only hides edit controls. [user change 4]
- D41 (2026-11-22) — Owner mode unlock = PIN (user choice over a hidden link). Salted SHA-256 hash in `js/owner-config.js`, set by `tools/set-pin.js`; the PIN itself is never committed. The repo is public, so a short PIN hash is guessable: accepted, it only hides controls (D40). [user change 4, T23]
- D42 (2026-11-22) — Owner edits are local drafts (`kb-timer-drafts`) shown only on the owner's device while owner mode is on, until published. Rename changes only the display `name`; file name and `id` stay. Remove = drop from `index.json` on publish (file kept in history). [user change 4, T24]
- D43 (2026-11-22) — Pictures by naming rule: an exercise without `clip` uses `clips/<clip-name>.webp`, then `.mp4`. Why: the owner can upload a clip later without editing any JSON or registry, and knows the file name from the exercise name (import preview shows it). Static hosting cannot list `clips/`, so the app tries the paths. [user change 4, T25]
- D44 (2026-11-22) — New routines are added by pasting a table (Markdown or TSV) produced in Claude Chat with a fixed prompt, converted offline by `js/import.js`; replaces the originally proposed in-app form (user: a form is too slow; a paper/print template was rejected: needs OCR). [user change 4, T26]
- D45 (2026-11-22) — Publishing = the app downloads changed routine files + `index.json`, the owner uploads them on github.com. No GitHub token in the app (keeps the app 100% offline, no key on the device). [user change 4, T27]
- D46 (2026-11-22) — SW routines match = request path contains `/routines/` (works under a GitHub Pages repo subpath). The network fetch uses `cache: 'no-cache'` so the browser HTTP cache (Pages max-age) cannot serve a stale routine; only ok responses are cached. [T22]

Keydown guard checks `ev.target.tagName` in INPUT/TEXTAREA/SELECT. Not browser-tested here. [T23]
- D48 (2026-11-22) — Owner PIN set by the owner (`tools/set-pin.js`); `js/owner-config.js` now holds its hash. Owner test relaxed from "empty hash" to "empty or 64-hex hash". Takes effect on phones with the next release (v10, T28) because js/ is cache-first. [user change 4]
- D49 (2026-11-22) — Drafts: `Drafts.rename` returns `{drafts, error}` (blank name = `name: required`); `apply` flags `unpublished`/`removed`, replaces `routine`+`name` for renamed files, and appends draft-only files as `ok` entries (T26 validates before storing). `app.js` keeps `baseEntries` (as loaded) and derives `entries` via `refresh()`, applying drafts only while owner mode is on; toggling owner mode refreshes. Rename/Remove/Undo are built per card (no new index.html IDs); Escape cancels rename. Not browser-tested here. [T24]
- D50 (2026-11-22) — T25: the name→file rule lives in `Routine.clipName`; `view.js` keeps a small local copy (same regex) so View stays dependency-free in browser and Node. Implicit media carries `fallback` (mp4); on image error `renderMedia` starts the fallback video once, then hides (handlers cleared, no retry loop). SW precache fetches both paths for exercise steps without `clip`, caching only ok responses. [T25]
- D51 (2026-11-22) — T26: `Import.toRoutine` treats a filled Block cell equal (case-insensitive) to the current block's name as the same block (chat tools often repeat it); a different name starts a new block. Outer pipes are optional, but a row whose first cell is empty needs its leading pipe/tab. Pause rows ignore cue cells. `weight` omitted when blank; `defaults.secPerRep` = 3. Added `Drafts.add(drafts, file, routine)` and pure `Import.preview` (blocks, targets, total, picture list) so app.js stays thin. Import panel closes/clears when owner mode turns off; editing any input disables Add until Check is re-run. Picture check = webp `Image` then mp4 `video` metadata load, "?" if untestable. Document keydown also ignores events inside `#import-panel` (buttons). Not browser-tested here. [T26]
- D52 (2026-11-22) — T27: `Drafts.publishFiles(entries, drafts)` takes the routines as published (no drafts) and returns a routine file for every draft routine not removed, plus `index.json` only when the list changes (a removal or a new file); a rename-only publish uploads just the renamed file. A file both removed and renamed is not written. `Drafts.changeCount` (draft routines + removals not already drafted) feeds the button label. Downloads use Blob + `<a download>`; "Mark as published" uses `window.confirm`. Keydown also ignores events inside `#publish-panel`. Not browser-tested here. [T27]
- D53 (2026-11-22) — Publish is refused unless `routines/index.json` loaded in this session (`Drafts.publishPlan`), so an empty/failed load can never produce an `index.json` that hides every published routine. Undo on a removed card only un-removes (keeps a rename or an unpublished import); Undo on a non-removed draft still discards it. [T29, review of T26/T27]
